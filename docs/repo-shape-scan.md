## Pattern

The first screen usually answers:

1. What is it?
2. What effect does it claim?
3. How do I install it?
4. What command proves it?

Common structure:

- short title and one-line promise;
- badges only if they support trust;
- one install block near the top;
- a tiny proof table or demo output;
- feature bullets after install, not before;
- details and caveats below the fold;
- examples and CI workflow included.

## Applied Here

`tool-tax` keeps the README short:

- one-line problem;
- install;
- scan command;
- measured example;
- CI budget command;
- limits.

Longer market notes live in `docs/`.
